## 投資知識如何落實在 App

1. **評估淨期望值，不以交易次數當成績。** 淨期望值可寫成「勝率 × 平均獲利 − 敗率 × 平均虧損 − 成本」，但勝率必須來自足夠且時間隔離的實際觀測，不能用模型自報信心代替。頻繁交易、忽略成本與只看過往績效是 SEC 投資人行為研究列出的常見問題。[SEC 原始報告](https://www.sec.gov/investor/tools/behaviorialpatterns.htm)
2. **資產配置和風險容量先於買點。** 投資期限、可承受損失及資金需要決定配置。多檔同產業股票不代表已分散共同風險。App 保留現金與單檔／整體曝險硬上限；缺少產業與相關性資料時不得宣稱已完成分散。[SEC 投資人教育](https://www.investor.gov/additional-resources/general-resources/publications-research/info-sheets/beginners-guide-asset)
3. **技術指標是描述，不是成功率。** MA 描述趨勢，RSI 描述近期漲跌幅相對強弱，ATR 描述波動；都不能單獨證明下一筆必賺。本程式 RSI14 為簡單平均版本，並非 Wilder 平滑版本，不能和平台上不同算法直接比較。只接受順序正確、日期唯一、OHLC 合法且當時已完成的資料。
4. **訊號、部位與執行要分別驗證。** 策略只提出方向／條件／有證據的目標；觸發後重讀帳務、行情，獨立確認股數。最後由確定性風控檢查價格、可賣庫存、交割、現金及曝險，才到券商 API。模型不得直接呼叫交易工具。
5. **報酬目標不能反推來湊風險報酬比。** 支撐、壓力、已完成區間可形成待檢驗假說。不能先想買很多，再把停損縮到正常波動內，或抬高目標以通過費稅門檻。股數過大時縮量或放棄；既有保護底線不下調。
6. **停損是觸發條件，不是成交保證。** 本機條件單依程式／網路持續運作；跌停、跳空、沒有買盤、當日新買股數不可賣，都可能造成超過名目停損的損失。App 不透過融資、賣空或當沖解決庫存限制。

### 本次實際加入的策略改善

- 指標輸入拒絕重複／倒序日期、不存在的日期、非有限值及收盤價超出當日高低價；不排序或補值來掩蓋錯誤。
- 即使歷史提供者錯誤回傳未來資料，策略入口也拒絕未來日期與盤中尚未完成的當日日 K。
- 股數確認每個可行 lot 增加 `estimated_break_even_exit_price`：在今日價格上限內，以合法 tick 搜尋覆蓋估計買賣手續費、賣出稅與滑價的最低退出報價。找不到回傳 null，不把它當成上漲預測。
- 策略提示明確要求比較成本、共同產業風險與樣本不足，不以交易頻率或資金使用率直接評為改善。
- 資料品質及執行修正套用各模式；既有研究策略不因本次成本算例而升級為已證實可獲利的預設策略。

### 可重現成本算例

以沒有股票代號的假設價格 30.05 買入、33 賣出，採 App 預設手續費率 0.001425、單邊最低20元、賣出稅0.003及退出滑價0.001。這些是可調的估計，實際折扣／零股最低費用依使用者券商合約，不能由通用 API 文件推定。

|---:|---|---:|---:|
| 1 | 盤中零股 | 找不到 | -38.083 |
| 10 | 盤中零股 | 找不到 | -11.83 |

## 官方委託參數逐項核對

官方使用 HTTP `POST /api/v1/order/place_order`，需同時提供 `contract` 與 `stock_order`。Python 的 `api.place_order(contract, order)` 是相同業務概念，App 實際走 HTTP，不混用 Python 物件或 CLI 旗標。[股票委託官方文件](https://sinotrade.github.io/tutor/order/Stock/)；[盤中零股官方文件](https://sinotrade.github.io/tutor/order/IntradayOdd/)

| 欄位 | App／API 值與核對 |
|---|---|
| `contract.security_type` | `STK`；普通股票資格另由契約與本機風控核對 |
| `contract.exchange` | 契約回傳的 `TSE` 或 `OTC`，不硬編全部 TSE |
| `contract.code` | 本次策略標的，與契約代碼完全相同 |
| `stock_order.action` | App `BUY/SELL` → API `Buy/Sell` |
| `price` | 正限價、合法 tick、今日漲跌停範圍，十進位計算後在 HTTP 邊界轉 JSON number |
| `quantity` | App 一律股數；`Common` 除1000一次，`IntradayOdd` 不換算 |
| `order_lot` | `Common`（整股）／`IntradayOdd`（盤中零股）；不誤用盤後 `Odd` |
| `price_type` | 明確 `LMT` |
| `order_type` | 明確 `ROD` |
| `order_cond` | 明確 `Cash`，不降級融資融券／借券 |
| `daytrade_short` | 明確 JSON boolean `false`，不使用字串或舊版 enum |
| `custom_field` | 6碼英數字、本機資料庫唯一識別，與回報完全核對；不是券商保證冪等鍵 |
| `account` | 核對後證券帳戶的 `{broker_id, account_id}`；不依賴預設帳戶、不傳金鑰或CA內容 |

整股範例：2000股 → `Common, quantity=2`；零股範例：999股 → `IntradayOdd, quantity=999`。普通委託單筆最多499交易單位；本程式限1000股普通股，因此上限499000股。499張依證交所115年6月從業人員課程第7頁明列「比照一般買賣帳戶」之數量規定核對：[官方PDF](https://dsp.twse.com.tw/public/static/downloads/brokerDepartment/A5--%E8%BF%91%E6%9C%9F%E4%BA%A4%E6%98%93%E7%9B%B8%E9%97%9C%E5%88%B6%E5%BA%A6%E8%AE%8A%E9%9D%A9%E9%87%8D%E9%BB%9E%E8%AA%AA%E6%98%8E-%E4%BA%A4%E6%98%93%E9%83%A8-A_20260526110131.pdf)。

程式的盤中零股送單目前保守從09:10開始，到13:30前；這是程式策略限制，不表示官方09:00–09:10不收單。既存日曆包含2026-12-07生效調整，沒有為本次修補擅改。官方現行申報／撮合及未來生效條文須區分：[交易制度](https://www.twse.com.tw/zh/products/system/trading.html?hl=zh-TW)、[零股辦法生效狀態](https://twse-regulation.twse.com.tw/TW/law/DAT08_print.aspx?FLCODE=FL007115)。

## 真實送單的已修正缺口

1. **重疊寫入與過期購買力。** Broker 層送單／撤單互斥，第二個寫入在網路前拒絕；寫入開始與完成都增加帳務變動序號並要求權威重查。寫入中取得的帳務不視為完整，沒有成交callback也不能沿用寫入前購買力。
2. **格式不是只靠模型遵守。** `stockOrderPayload()` 先以嚴格 schema 驗證，再檢查本機未送出狀態、合法數量、商品、交易所、價格及已核對帳戶；錯誤在 HTTP 前回報 `NoSubmissionError`。
3. **回報帳戶與識別。** 送單／撤單／核對同時檢查選定帳戶、委託 ID、交易所、tag、方向、股數、限價與條件。明確 `Filled` 但數量未完整、成交倒退或超額都不能當成成功完成。
4. **撤單期間成交。** 先取得最新本機可核對累計成交量，再送撤單；若回傳較舊成交量則保留不確定，不釋放庫存。`CANCEL_PENDING` 不等於已撤成功；下一筆須等待終態與帳務重讀。
5. **未知結果不重送。** HTTP timeout、無法解析或回報不符可能發生在券商已受理之後，所以一律保留 `UNKNOWN`，依券商 ID／唯一 tag 核對。券商快取沒查到也不自動認定未送出。
6. **流動性及超大持倉。** 對手方深度為零不假設可成交。智慧保護的大額整股提案最多499張，後續庫存只在前單終結及重查後再評估；不平行拆單。

API 回應 `PendingSubmit` 是仍在送出，不是成交；`Submitted`、`PartFilled`、`Filled`、`Cancelled` 分別處理。官方1.7.6起 Trade 由回報自動更新；平時用事件／快取，登入、缺報或寫入後才權威重查。[狀態與快取健康文件](https://sinotrade.github.io/tutor/order/UpdateStatus/)

盤中零股不能直接改價，只能減量；本程式不做零股原單改價，而是先撤單、確認、再以最新行情與庫存另評估。改量需要其他設計時也不能增加股數。帳戶外部改單不會被本機靜默接受成原策略的精確委託。[零股改單規格](https://sinotrade.github.io/tutor/order/IntradayOdd/)

行情使用訂閱，不改成盤中輪詢歷史K線。沿用單一登入、歷史快取、回報快取與限流退避；沒有將官方上限當成正常執行頻率。[官方使用限制](https://sinotrade.github.io/tutor/limit/)

## 策略研究仍需哪些證據

本次沒有新的獲利率宣稱，也沒有把 MA／RSI 參數調到這份資料最好看。現有本地資料是2025–2026、預先指定10檔股票的未還原日資料，缺真實盤中零股五檔與完整動態證券主檔；它只能做流程／近似研究，不能拿來證明全市場或零股策略有超額收益。既有2024研究方案與限制見 [`V0.2.5_VALIDATION.md`](V0.2.5_VALIDATION.md)。

後續可完善的研究順序：

| 工作 | 驗證方式／上線條件 |
|---|---|
| 真實執行品質 | 分市場記錄委託價、實際分筆成交、時間、費用與拒單；不能把限價當成交價 |
| 策略增益 | 固定基準與假說，按時間隔離開發／驗證；同一資料、費稅、額度、滑價下比較，完整保留失敗組 |
| 交易機會成本 | 與現金及適當股市基準比較曝險、回撤、周轉率和尾端風險；基準是否含股息需註明 |
| 組合分散 | 先補可追溯產業分類與歷史相關性，再研究產業上限；目前不虛構缺少的相關性矩陣 |
| 公司行動 | 還原除權息、分割及停復牌，避免價差被誤判趨勢或ATR；資料缺失繼續停止新增風險 |
| 成交品質 | 比較Common與IntradayOdd各自價差、有效深度、等待及部分成交，不能假定整股永遠比較便宜 |

策略候選最多20檔是研究／監測範圍，實際持倉數依訊號與風控；不硬塞股票。原現金25%、單筆扣保留後可投資資金10%、單檔20%、曝險75%、日新增20%／5筆、日損失2%維持上限。
