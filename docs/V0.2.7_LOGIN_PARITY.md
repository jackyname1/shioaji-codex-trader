# 0.2.7 登入與 Shioaji Pro 比對

比對官方 [shioaji-pro-app](https://github.com/Sinotrade/shioaji-pro-app/tree/be4cbd3073df2625db0d51f767c812a27f79cb8e)（提交 `be4cbd3073df2625db0d51f767c812a27f79cb8e`），及 [Shioaji 1.7.8 發行版](https://github.com/Sinotrade/Shioaji/releases/tag/v1.7.8)。Pro 的公開前端可檢查；其引用的原生桌面模組未公開，沒有把未取得的原生實作當成已讀取證據。

| 項目 | Pro 公開實作／官方版本 | 本程式 0.2.6 | 0.2.7 修正 |
|---|---|---|---|
| 內建 SDK | `SHIOAJI_VERSION` 為 1.7.8 | 固定 1.7.7 | Windows／Linux 同步 1.7.8，下載檔逐一驗證官方 SHA-256 |
| 登入快取 | `src/lib/tauri.ts` 啟動環境未強制 `SJ_HOME_PATH` | 強制為 App 的 native-service 目錄 | 移除強制值，採 SDK 預設；若用戶明確指定則保留，不刪除舊資料 |
| Windows 用戶環境 | 原生程序繼承環境 | 精簡環境省略 APPDATA／LOCALAPPDATA 等 | 明確傳遞 Windows 用戶目錄、時區、代理及 SDK 相關設定；不傳遞其他服務的金鑰 |
| 本機 HTTP 驗證 | Pro 發行說明要求 localhost Bearer 關閉 | 未明確設定 | `SJ_HTTP_AUTH=false`，只綁定 127.0.0.1，保留 SDK 跨站防護 |
| 啟動命令 | `server start --no-open`，正式模式加 `--production` | 相同命令 | 保持前景子程序及正式行情模式，金鑰只透過環境傳入 |
| API 與登入狀態 | 先等 `/info`（45 秒），再等健康工作階段（90 秒） | 先等 `/health`，最後讀 `/info` | 分兩階段等候；版本／模式不符、HTTP 401／403立即停止；恢復中、過期權杖不視為登入成功 |
| 重新登入 | Pro 先確認自己管理的程序已停止；不終止外部服務 | 強制終止要求送出即允許繼續 | 等實際 exit；逾時仍未退出則阻止下一次登入；已以訊號退出的程序可重連 |
| SIGN_TIME | 原生 SDK 回報簽章拒絕 | 加入 Windows 校時與 UAC | 完整刪除校時、按鈕與 IPC；保留原生安全代碼，不認定是 Windows 時間錯誤 |

`SJ_HTTP_AUTH` 由下載後的官方 1.7.8 CLI `server start --help` 核對；不新增未公開的簽章有效期限參數。官方 1.7.8 發行說明列有每日維護時段權杖更新、每次登入補入委託快取及連線修正。這些是已確認的版本差異，並不證明使用者那次 SIGN_TIME 的唯一原因。

## 驗證範圍

- 單元測試覆蓋兩階段 API 就緒、恢復中健康狀態、版本／模式不符、HTTP_AUTH、環境傳遞、SIGN_TIME 不重試、CA 失敗一次行情回復、強制終止等待與無法終止時阻擋重新登入。
- Linux／Windows 執行完整測試；Windows 來源及封裝 GUI 驗證保存登入、原生失敗安全代碼、移除校時介面、正式行情模式檢查、重試後 API／工作台連線，以及零真實委託。成品核對實際內建 CLI 版本與資源雜湊。
- GUI 使用隔離子程序與 HTTP 回應；官方二進位版本與資源另行檢查。沒有使用使用者的 API 金鑰，不能把測試成功等同該帳戶已完成真實登入，也沒有透過停用健康檢查來顯示成功。

本次不修改交易策略、授權風控或實盤啟用狀態。有效 CA 仍只關係實盤委託，登入未完成不追加 CA 警告。
