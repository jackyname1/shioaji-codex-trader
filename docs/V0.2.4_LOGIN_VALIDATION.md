# v0.2.4 登入修復驗證

## 已確認的問題與證據

使用者回報 0.2.3 顯示「Shioaji 登入未完成，請核對 API Key、Secret Key、生產權限及允許的 IP」。提供的診斷顯示 /health 嘗試 12 次、成功 0 次，沒有 HTTP 狀態碼、程序輸出或退出碼。舊程式漏算重複失敗，因此 failures=1 不能解讀為另外 11 次成功。

比對 v0.2.2 與 v0.2.3：credentials.ts、broker-runtime.ts、broker/health.ts、prepare-broker.ts 及固定的 Shioaji 1.7.7 執行檔鎖定資料均相同。現有紀錄不足以確認這次失敗是金鑰、IP、CA、網路或程序異常，不能聲稱已重現使用者帳戶故障。

## 修正範圍

- 接收內建程序的兩個輸出管道，只轉為固定錯誤代碼。每管道暫存上限 4096 字元，完成後清除；不寫入檔案、不匯出原始輸出或私人路徑。
- 保留程序退出碼、已知訊號、等待時間及 CA 恢復標記。區分已知 CA、時間、網路、權杖、健康檢查與不明程序退出，不把不明失敗直接當成金鑰錯誤。
- 僅明確 CA 錯誤嘗試一次不載入 CA 的行情登入。保持原加密設定，重新登入仍使用原值；金鑰拒絕、不明退出與第二次失敗均停止。行情成功不代表實盤 CA 或交易權限就緒。
- 健康檢查失敗逐次計數；重連清除上次健康狀態。
- GUI 驗證包含程序退出、SIGN_TIME 安全代碼、退出碼 17、錯誤可見、保存設定可用、後續重新連線成功及零真實委託。

## 驗證方式與限制

使用 Node 測試、真正的隔離子程序以及 mock HTTP／程序測試；不使用使用者 API 金鑰，不接實際券商帳戶。測試涵蓋分段輸出、CA 錯誤的一次恢復、拒絕重試、健康恢復與過期權杖、每次失敗計數、登入後程序退出及資訊不外洩。

Windows 來源與封裝 GUI 均由 GitHub Actions 執行。README 使用相同版本的 Windows 隔離測試畫面，來源與雜湊記錄於 docs/screenshots/provenance.json。實際帳戶登入仍需使用者安裝後驗證；若仍失敗，需新版診斷才能進一步判定。
