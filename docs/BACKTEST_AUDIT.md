# 回測稽核與驗證範圍（v0.1.5）

本版修復策略生命週期與跨日未成交掛單，未依個別回測盈虧放寬風控或改寫交易結果。獲利與程式正確性須分別驗證。

## 已檢查的路徑

| 範圍 | 行為與驗證 |
| --- | --- |
| 歷史資料／選股 | 正規化重複 K 線；拒絕衝突；當時每日股票池、此前已完成日 K 與可知日曆；未來價格、成交量及未來入池股票不進入當前快照 |
| 策略生命週期 | 成功啟用後持續到新盤中策略成功接替，跨日與重啟保存；檢討不替換；舊策略仍保留原期限；模型故障與預算停止仍生效 |
| 訊號與掛單 | 完全未成交且確認撤銷的 ROD 可於次交易日重驗後掛單；同日、任何成交、未知結果或遭拒不自動重試；新掛單仍須通過全部風控 |
| 成交模型 | 提交後下一筆行情才可能成交；有限深度、部分成交、零深度、漲跌停及收盤撤單；不根據同根 K 線高低價猜測先後路徑 |
| 持倉保護 | 今日新增庫存不可當沖；已存保護、跳空及無買盤等待；費用後保本價格不是保證成交價格 |
| 現金／交割 | 買入即扣款、掛單預留、賣出 T+2 可用；已知臨時休市與 11:00 入帳；待收款計入淨值但不可提前再投入 |
| 帳務／績效 | 獨立 FIFO 含買費成本重算；部分賣出分攤成本；已實現＋未實現＝淨損益；完整平倉交易與部分成交分開計數 |
| 呈現／匯出 | 測試紀錄視窗直接匯出；JSON／Markdown 包含帳務核對、期末估計賣出費稅、估值時點及績效狀態；來源及封裝 Windows GUI 均驗證 |

## 九項獨立帳務核對

`backtest-audit.ts` 由原始成交重新建構成本與資金，不沿用報表上的損益總數：

1. 成交依時序且晚於提交，不超過回測截止。
2. 成交識別不重複。
3. 股票、方向、單位、限價、累計股數與委託一致。
4. 成交金額等於價格乘股數。
5. FIFO 成本含買費，未超賣／當沖，期末庫存與成本一致。
6. 費稅依每筆委託累計，與設定及總數一致。
7. 起始資金、成交數、委託數與總成本一致。
8. 成交現金流等於期末現金加待收交割款。
9. 重算淨值、已實現／未實現及費用前後損益一致；容許分幣四捨五入。

新回測核對失敗會標記 FAILED。另行標出期末持股最後行情距當日收盤或模擬截止超過五分鐘，以及沒有有效估值時間的情況。估計剩餘賣出費稅按合法股數分單計算最低費用及交易稅；只是末價成本估算，沒有模擬已賣出、價差、滑價、排隊、企業行動或期末清算可行性。

## 固定公開日 K 回歸檢查

以版本庫既有十檔公開日 K 面板及固定程式規則檢查引擎，不呼叫 Codex 或券商，也沒有參數搜尋。每組起始 100,000 元、空庫存、每五個交易日分析；期間與成交情境在執行前固定。這些資料過去已參與研究，不能稱為新樣本外資料，更不能替代使用者的分鐘行情及 Codex 策略。

三組已觀測交易日的策略覆蓋分別為 61/61、38/38、38/38。保留所有組別及負結果，未選擇只呈現正報酬。公開資料尚有未調整權息、存活者偏差、固定股票池及不完整歷史交易／交割日曆限制，無法驗證真實零股成交。

重現：

```bash
npm run build
node scripts/check-backtest-accounting.mjs
```

程式保存每組完整壓縮紀錄、設定與資料 SHA-256 至預設忽略的 `private/backtest-accounting`，包含失敗或虧損結果。

## 獲利驗證尚未完成

正淨值、帳務核對通過及單元測試通過均不等於實盤合格。原三個月報表與執行紀錄無法還原每分鐘行情；需要同一次回測另匯出的完整行情 JSON 才能在原資料上重跑修正版。後續須先固定策略與成本／風險條件，再使用未參與調整的時間區間及保守成交情境驗證，並在模擬交易中核對分析延遲、實際五檔、拒單與交割。現有研究面板不得重新標記為未看過的資料。
