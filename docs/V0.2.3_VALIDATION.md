## 根因與修復

| 發現 | 證據及處理 |
|---|---|
| 智慧退場未使用 | 40 個 BUY 全未填 trailing_activate、trailing_fraction、reward_target；21 REBOUND、16 IMMEDIATE、2 BELOW、1 ABOVE，不能誤稱全部在等跌破。綜合模式補上 ATR 移動保護與含成本保本，保存高點、上移底線及觸發意圖。 |
| 同股等待排斥其他機會 | 程式原先遇到模型 BUY 就排除該股。改成模型及三路程式方案競爭，先看實際確認、再看成本／風控可行性及分數；原方案不放寬。 |
| 資金閒置有多重原因 | 期末有 42,696 元 T+2 賣款尚未成為購買力，最後一天日損失達限。新增分類診斷，保留現金與交割限制，動態偏好只分配給合格交易。 |
| 弱利潤被費用侵蝕 | 毛利 1,642.5 元扣 1,053 元費稅只剩 589.5 元。按最終股數檢查淨利、成本倍數、普通風險與跳空壓力，避免不經濟碎單；沒有擅改券商最低費用。 |
| 保護限價與滑價模擬不一致 | 賣價設在當前買價，扣滑價後反而永遠不符合委託最低價。模擬保護使用有界限價容忍範圍，仍需下一事件、深度與漲跌停範圍；不憑空產生買盤。 |
| 重複拒單及候選失敗 | 原始 16 次風控訊息包含整／零股混合原因，不能全歸咎於建議股數。新增每市場預檢、持久化原因去重、最終股數再驗證；未知候選限一次完整重分析後失敗即停。 |
| 參數範圍與策略格式不一致 | 25% 單筆上限的敏感度測試抓到程式規則欄位仍限 20%，整輪產生格式錯誤。規則值限制在其合法範圍，保留使用者硬上限及獨立動態配置。 |
| 跨計畫追蹤重設 | 原本只保留模型追蹤。保留未逾時程式追蹤，只有訊號鍵一致才延續確認與原到期日；變更方案不沿用舊低點。 |
| 啟動模式與 UI | 一般啟動回到模擬且不給實盤自動授權；持倉詳情／主圖來源同步，核心智慧條件優先顯示，避免新增欄位把重要資訊擠出面板。 |

review_only 不進場、盤後／過期報價、資料不足、日損失鎖定、當日零股不可賣等均保留，沒有當作 Bug 解除。

| 額外跳空壓力／壓力風險上限 | 無獨立檢查 | 3%／權益 2.5%，不取代 1.25% 普通風險 |
