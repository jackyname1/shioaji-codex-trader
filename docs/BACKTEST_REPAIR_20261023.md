## 已確認的原始碼缺陷與修復

| 缺陷 | 程式路徑／修改 | 對應驗證 |
| --- | --- | --- |
| 期限錯誤被一般訊息遮蔽 | `strategy.ts validateAnalysis` 原本拋出「模型回覆啟用期限不符」，`backtest.ts` 的訊息白名單不包含「模型」；改成具型別錯誤與穩定錯誤碼 | 9/9 期限案例、完整合成回放、JSON／Markdown／UI 錯誤碼 |
| 模型自行計算回覆期限 | `engine.ts snapshotFromBundle`、`codex.ts analyze/run` 將程式計算的 `decision_deadline_at` 放入快照及輸出 Schema；提示要求原樣複製 | 實際 Runner 接收的 Schema 與提示測試 |
| 回覆延遲會延長期限上限 | 原先上限是 activation now + plan_max_minutes；改成 snapshot asof + 本機設定，快照本身仍受 timeout + 30 秒限制 | 延遲回覆不能延長快照窗口 |
| 拒絕新提案會使舊策略停止進場及撤單 | `backtest.ts decision`、`service.ts performDecision` 僅在存在有效舊策略且屬明確輸出驗證錯誤時保留；資料、帳務、持久化、券商、終止性 SDK 及額度故障仍封鎖 | 舊策略／保護／掛單原樣保留；9/9 拒絕後按舊條件成交；資料庫與網路錯誤不取得 fallback |
| 等待次數易被誤解為機會數 | `entry-diagnostics.ts` 另外統計策略 ID／股票唯一訊號及各等待原因，排除保護賣出的等待狀態 | 100 次掃描只算一個訊號、原因重疊、跨日重掛不重算 |
| 缺少獨立委託與失敗 CSV 入口 | `backtest-export.ts`、桌面 `index.html/main.ts` 新增兩種格式，保留取消／拒絕／未成交單與缺資料日期 | 格式內容測試及來源／封裝 GUI 的真實 preload／IPC／儲存路徑 |
| 期末估值過期仍可能顯示 COMPLETED | `backtest.ts` 完成帳務稽核後，若期末持倉估值缺漏或過期，改為 PARTIAL 並記錄 STALE_VALUATION | 有成交、帳務平衡但持股末價過期的完整回放 |
