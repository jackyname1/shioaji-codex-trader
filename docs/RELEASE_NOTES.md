# v0.1.9 — Codex 故障停止與 Windows 圖示

- Codex 失敗改用安全錯誤代碼區分 DNS、TLS 憑證、代理驗證、連線拒絕／重設、串流中斷、HTTP 服務錯誤、登入、權限、額度、限流與回應逾時。完整 JSON 保留分類及代理／自訂 CA 是否存在，不匯出位址、密碼、私人路徑或 SDK stderr。
- 網路、登入、權限、模型、額度、限流或逾時故障會立即停止歷史回放及其餘比較，保存當下 PARTIAL 結果，不再跳到後續時段持續呼叫。即時模式停止自動 Codex 呼叫，帳務與成交仍持續核對；出場條件保留，未確認數量不送單。
- 「測試連線」收到有效模型回應，或重新分析通過策略核對後，才解除即時 Codex 故障狀態。恢復不解除暫停買進、緊急停止或實盤鎖定；先前失敗的日策略仍需重新分析。歷史測試需重新執行，不能從帳務檢查點接續。
- 保留明確設定的 ALL_PROXY、大小寫不同的代理／自訂 CA 環境變數；不繞過代理或停用 TLS 驗證。合併 SDK 與回放引擎對同一失敗的重複訊息，保留實際模型和安全診斷。
- 移除完整系統匣圖示在 Windows 工作列上的疊加，避免出現兩個重疊圖示；主視窗固定使用 ICO 和相同應用程式身分，執行／暫停等狀態留在系統匣。
- Windows 完整測試降低同時啟動的測試程序數，保留所有測試及保守的本機鎖核對；來源與打包後 EXE 都驗證不疊加圖示及圖示資產可讀。
- 發行者仍需要可信程式碼簽署身分。未配置憑證時 WINDOWS-SIGNATURE.json 如實標記未簽章、publisher=null；產品名稱與圖示不能取代 Authenticode，亦不保證 SmartScreen 信譽。

先從舊版系統匣選擇「結束程式」，再開啟新版。v0.1.7 的通用連線錯誤紀錄無法回推底層原因；若新版仍斷線，請匯出包含安全錯誤代碼的最新紀錄以進一步核對。

# v0.1.8 — 回測資料與完整條件核對

- 自動股票池改為每天讀取前一交易日歷史成交金額排行，依設定的資料池上限挑選；保存每一天的成員及資料日期，新入池股票不會提前出現在選股快照。歷史排行也會快取，日期不符時拒絕替代；指定股票仍是明確的固定池。
- 複合買賣標準新增受限的結構化 conditions（價格、均線、RSI、支撐壓力等）；與原價格條件全部同時成立才確認股數，股數回覆後及送單前再次核對。缺指標或未完成／未來日 K 時阻擋，不執行模型生成的程式碼。舊計畫與報表保持可讀，新策略需完整列出額外條件。
- 修正盤後檢討仍沿用晨間歷史快取的問題；當日日 K 在 13:40 後且有收盤資料時才可納入。當日參考價與漲跌停估算仍取前一交易日，不被盤後更新改寫。
- Codex 額度耗盡或限流時立即停止歷史回放，取消未成交模擬委託，保存停止時刻的 PARTIAL 結果，後續比較不再重試；不跳過數量確認送單。恢復後重新執行測試，並非從帳務檢查點續跑。
- 股數確認加入雙邊手續費、賣出稅及停利價差估算；報表拆分費用前損益、已支付成本、成本占起始資金比例及賣出委託數。近似撮合、小樣本與 Codex 延遲限制更明確。
- 保留單一完整策略及五分鐘檢查，直達與 1–60 倍連續秒數模式不變；Windows 當前程序鎖不再啟動不必要的 PowerShell 探測，其他舊鎖仍保守核對。
- Windows 舊程序鎖改以 .NET 唯讀查詢，避免冷啟動載入 Get-Process 模組造成五秒逾時；整體探測仍有 15 秒上限，逾時或權限不足維持 unknown，不刪除未確認的鎖。小螢幕持續顯示近似成交警示。
- 新增每日池、歷史時間界線、盤後快取、複合條件前後核對、額度停止與費用核算測試，以及 Windows 來源與成品介面品質／成本驗證。測試僅使用隔離資料，不送出實盤委託。

歷史零股成交、排隊、滑價及企業行動仍是近似，不代表實盤績效。每日資料池聯集最多 100 檔、行情最多 300 萬筆；超過時需分段，不會靜默截斷。

# v0.1.7 — 直達與加速播放

- 明確分開「直達觸發點」與「加速播放」兩種模式，直達模式停用倍速控制。
- 加速限制為 1–60 倍，預設 10 倍；模擬秒數連續前進，時間到達行情事件後才處理該筆資料，每五分鐘檢查買賣條件。
- 暫停、Codex 選股、股數確認與事件處理期間凍結時鐘；恢復時不補跳等待期間的秒數。
- 秒數顯示與行情資料截止時間分開，畫面可連續播放，圖表及決策仍只看到已處理資料。
- 新增速度限制、時間比例、暫停恢復、事件邊界、兩模式成交一致性及 Windows 來源／成品介面秒數驗證。

# v0.1.6 — 完整 Codex 歷史回放

- 歷史回放移除程式策略切換，統一 Codex 選股、觀測股買進條件與持倉出場條件，觸發後再次確認數量。

# v0.1.5 — 本機實盤紀錄恢復

- 修正 Windows 本機資料庫初始化的相容問題：使用使用者目錄 ACL，不對 SQLite 執行 Unix chmod。
- 舊資料庫鎖改用 Windows 唯讀程序查詢，避免以訊號探測要求程序終止權限；可確認已結束或 PID 重用的舊鎖會安全清理，擁有者不明時仍保留原紀錄與帳務唯讀。
- 修正鎖寫入失敗未關閉檔案，以及 SQLite 關閉後遇到暫時 unlink EPERM 使同一程式無法重試的問題。
- 診斷新增「重試本機紀錄」，直接重新開啟原資料庫並沿用已登入的 Shioaji；失敗時維持帳務讀取，成功後清除舊錯誤並保持自動交易關閉。
- 診斷會顯示失敗的本機步驟，不匯出私人路徑；同時修正診斷 JSON 匯出按鈕。系統匣與工作列同步顯示本機紀錄待修復。
- 修正 Windows 建置時官方 Shioaji 執行檔的解壓縮逾時，改用系統內建 ZIP 解壓工具並保留 SHA-256 驗證。
- 新增隔離的 EPERM、鎖清理、原紀錄保存、唯讀帳務、GUI 重試失敗及成功恢復驗證，測試不登入使用者帳戶、不送出實盤委託。

開啟修復版前，請先從舊版系統匣選擇「結束程式」。首次開啟會嘗試恢復原紀錄；仍顯示帳務唯讀時，可在「診斷」按「重試本機紀錄」。
